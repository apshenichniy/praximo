# PROTOTYPE — Mini App screens (wayfinder [#15](https://github.com/apshenichniy/praximo/issues/15))

Throwaway TanStack Start app: три радикально разных варианта минимального
Telegram Mini App коуча (расписание, сессии, клиенты) против доменной модели
`docs/spec/domain-model.md`. Всё замокано, ничего не сохраняется. Не продакшен.

## Run

```sh
bun install
bun run dev   # http://localhost:3001
```

Один роут `/`, переключение вариантов — `?variant=A|B|C`, плавающая панель
внизу или стрелки ←/→.

## Варианты

- **A «Табы»** — нижние табы Расписание/Клиенты, agenda-список по дням,
  артефакты — раскрывающиеся секции внутри карточки сессии.
- **B «Сегодня»** — hub-and-spoke: hero-карточка ближайшей сессии,
  «требует внимания» (сбои генерации, непринятые инвайты), лента свежих
  артефактов; Mini App как архив доставленного ботом.
- **C «Клиенты-first»** — telegram-native списки: календарная полоска недели +
  клиенты; сессии — таймлайн внутри клиента, артефакты — строки таймлайна.

## Что проверяем (из тикета)

1. Состав экранов и навигация: расписание, список/карточка сессии,
   список/карточка клиента.
2. Где живут артефакты (Brief / Debrief / Mentor Review) относительно
   сообщений бота.
3. Действия жизненного цикла сессии в UI: планирование, перенос (mutate),
   отмена. Ручной «mark no-show» из тикета устарел: по `web-room-sessions.md`
   неявку фиксирует реконсайлер — в UI она показана как автоматическая отмена.
